## 2025-02-28 - SQL Injection in DatabaseManager.update_memory via f-string Dictionary Key Interpolation
**Vulnerability:** A SQL injection vulnerability exists in `DatabaseManager.update_memory` where the SET clause is constructed using an f-string over dynamic JSON/dictionary keys (e.g., `set_clause = ", ".join([f"{k} = ?" for k in serialized.keys()])`). Since dictionary keys might originate from unsanitized user inputs within the update payload, this could allow arbitrary SQL keyword injection.
**Learning:** Constructing SQL queries directly from dictionary keys of user-provided data is dangerous even if the values are properly parameterized. Wrapping the keys in double quotes prevents simple injection but can still be bypassed if the dictionary keys contain double quotes themselves.
**Prevention:** Strictly quote dictionary keys AND escape any internal quotes when dynamically generating SQL clauses to prevent injection (e.g., `f'"{k.replace(\'"\', \'""\')}" = ?'`) and use inline suppressions (like `# nosec B608`) to silence valid string formatting when dynamically passing table names if the source is fully controlled.
