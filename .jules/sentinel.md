## 2024-11-02 - Mass Assignment & SQL Injection in Dynamic Column Generation
**Vulnerability:** Mass assignment vulnerability leading to unauthorized column updates and potential SQL Injection in `DatabaseManager.update_memory()` in `Pinak_Services/memory_service/app/core/database.py`. The `set_clause` is generated directly from arbitrary dictionary keys `", ".join([f"{k} = ?" for k in serialized.keys()])`.
**Learning:** Even when using parameterized queries (for values), generating column names dynamically from user input (or dictionaries that originate from user input like `updates`) without whitelisting or using `.isidentifier()` allows attackers to update protected fields or inject SQL into the column name structure. `MemoryService.update_memory` filters out some `forbidden_keys`, but fails to filter non-identifiers or new system columns, acting as a partial mitigation that still permits mass assignment on unfiltered columns and SQL injection via specially crafted keys.
**Prevention:** When dynamically creating `UPDATE` statements, ALL dictionary keys must be strictly validated against a hardcoded whitelist of allowed schema columns. Furthermore, `k.isidentifier()` provides a foundational defense against SQL injection via column names.
