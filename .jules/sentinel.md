## 2024-05-18 - SQL Injection in Memory Service

**Vulnerability:** Found multiple instances of string formatting used to construct SQL queries, leading to potential SQL injection vectors. Notably, dynamic column names in `UPDATE` queries were not being correctly escaped or parametrized (which isn't fully possible with column names). Table names were also dynamically interpolated, but they are internally generated by dictionary lookups mapping string layer names to hardcoded table names.

**Learning:** When using dictionaries to construct update queries, column names must be double quoted and internal double quotes escaped `"{}"` to prevent injection if the dictionary keys come from untrusted input. `bandit` tool will still flag any f-string or formatting used for SQL execution, so inline `# nosec B608` should be added when we are certain the parameters are safe or properly escaped, and static analysis fails to ascertain that. Python versions prior to 3.12 do not allow backslashes within f-string braces, so `.format()` should be used.

**Prevention:** Ensure dynamic SQL construction escapes column names and table names if they are not strictly validated against a hardcoded allowlist. Use `# nosec B608` thoughtfully after mitigating the real injection risks.
