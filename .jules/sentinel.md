## 2026-06-12 - [Critical] Fix SQL Injection in dynamic UPDATE queries
**Vulnerability:** A critical SQL Injection vulnerability exists in `app/core/database.py` inside `DatabaseManager.update_memory`. The dictionary keys in the `updates` dictionary are concatenated directly into the `SET` clause of the SQL string (`set_clause = ", ".join([f"{k} = ?" for k in serialized.keys()])`) without validation. Because users can supply arbitrary JSON objects as updates, an attacker can construct keys like `"tenant = 'HACKED', client_id"` which bypass the API's `forbidden_keys` check (since `"tenant = 'HACKED', client_id"` is not exactly `"tenant"`) and manipulate any fields, or inject arbitrary SQL clauses.
**Learning:** Dynamic query construction that uses dictionary keys derived from external input without strictly validating those keys as safe identifiers introduces severe SQL Injection and Mass Assignment vulnerabilities, even when the values are parameterized.
**Prevention:** Always validate that dynamically constructed column names (e.g., dictionary keys) are strictly valid identifiers (using `.isidentifier()`) and ideally check them against an explicit list of allowed column names before adding them to a SQL string.
