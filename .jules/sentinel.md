## 2025-03-08 - SQL Injection via Unquoted Keys in Dynamic UPDATE Query
**Vulnerability:** In `Pinak_Services/memory_service/app/core/database.py` (specifically `update_memory`), dictionary keys were used to construct a `SET` clause dynamically (e.g., `f"{k} = ?"`). Because the keys weren't validated or quoted, arbitrary keys provided to the update operation could result in an SQL injection vector.
**Learning:** Even when the table name is strictly validated via a `table_map` (from the `layer` argument), the keys within `updates.items()` must be handled defensively. When using dictionary keys to build SQL statements dynamically, they need to be strictly validated or at a minimum enclosed in double quotes (e.g., `f'"{k}" = ?'`) to prevent SQL injection in SQLite.
**Prevention:** Avoid dynamic query building using untrusted input. If dynamic fields are necessary, ensure dictionary keys are explicitly enclosed in quotes (`"..."`), or better, validate them against a strict whitelist of known schema columns before appending them to the query string.
