## 2024-05-18 - Fix Dynamic SQL Key Injection and Tenant Bypass in `update_memory`
**Vulnerability:** The `update_memory` function in `database.py` dynamically constructed SQL `SET` clauses directly from the dictionary keys of the `updates` parameter without validation. This allowed attackers to perform SQL injections by supplying keys like `content = (SELECT 'hacked')` or `tags = '[]' --`, and permitted bypassing tenant multi-tenancy boundaries by sending a `tenant` key update payload (e.g. `{"tenant": "hacked"}`).
**Learning:** Even when using parameterized values (`?`), constructing the column names dynamically from raw input completely bypasses the safety of parameterization, leaving the application vulnerable to injection or unauthorized modifications of critical identifiers.
**Prevention:** Always validate dynamically generated column names using `key.isidentifier()` to ensure they are valid Python identifiers, and explicitly deny updates to protected/immutable scope identifiers like `id`, `tenant`, and `project_id`.
