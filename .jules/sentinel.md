## 2024-08-24 - SQL Injection in Memory Update
**Vulnerability:** SQL Injection in Pinak_Services/memory_service/app/core/database.py `update_memory` and potentially other methods. The code concatenates dictionary keys directly into the SQL query without proper escaping: `set_clause = ", ".join([f"{k} = ?" for k in serialized.keys()])`. Although SQLite parameterization is used for values, the column names (keys from the user-provided updates dictionary) are not validated or escaped, allowing an attacker to inject SQL.
**Learning:** In SQLite, dynamic column names must be strictly validated or properly double-quoted/escaped. Trusting dictionary keys from user updates payload as column names directly is a serious vulnerability. Also Bandit f-string warnings (B608) are triggered and need to be explicitly suppressed when escaping is implemented via `.format()` and inline comment.
**Prevention:** Strictly validate dynamic column names against a known safe schema or properly double-quote and escape internal quotes for all dynamically constructed queries using user-provided dictionary keys. Use `'"{}" = ?'.format(k.replace('"', '""'))` for SQLite dynamic SET clauses and suppress Bandit B608.
