## 2026-07-14 - Fix SQL Injection in update_memory
**Vulnerability:** SQL injection exists in `Pinak_Services/memory_service/app/core/database.py:update_memory` where user-controlled dictionary keys (from `updates`) are directly interpolated into the `SET` clause without validation (`set_clause = ", ".join([f"{k} = ?" for k in serialized.keys()])`). This allows bypassing the `WHERE id = ?` constraint using comments and dummy bindings (e.g. `role = 'admin' WHERE id = '2' OR ? IN (?, ?, ?) --`).
**Learning:** Even when parameterized queries (`?`) are used for values, dictionary keys used to dynamically construct SQL statements must be strictly validated. Python's `str.isidentifier()` provides a simple defense. Bandit flags dynamic string interpolation but cannot verify if the components are sanitized.
**Prevention:** Always validate all dynamic column names or table names using an allowlist or strict format check (like `isidentifier()`) before interpolating them into SQL.
