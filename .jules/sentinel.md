## 2024-10-28 - Dynamic SQL Injection and Mass Assignment in Memory Update
**Vulnerability:** The `update_memory` function constructed SQL UPDATE statements by directly iterating over user-provided dictionary keys and interpolating them into the `SET` clause (`set_clause = ", ".join([f"{k} = ?" for k in serialized.keys()])`). This allowed clients to perform Mass Assignment (modifying protected fields like `id`, `tenant`, or `project_id`) and dynamic column generation/SQL injection (by injecting arbitrary SQL via dictionary keys like `content = 'hacked' --`).
**Learning:** It existed because Python dictionaries allow arbitrary string keys, and the code trusted the `updates` payload implicitly without enforcing a whitelist or checking if the keys were valid identifiers before injecting them into the SQL query string.
**Prevention:** Never trust user input to dynamically generate SQL query structures (like column names). Always enforce a strict whitelist of allowed columns and validate keys using `.isidentifier()` before incorporating them into a SQL string.
