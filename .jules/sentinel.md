## 2025-05-24 - SQL Injection Risk via Unquoted Dictionary Keys in SET Clause
**Vulnerability:** The SQLite `update_memory` function was constructing dynamic `SET` clauses directly using dictionary keys via `f"{k} = ?"`. Unquoted keys present a SQL injection vulnerability if a malicious actor controls those keys.
**Learning:** Even when parameterized execution `execute(query, params)` is used for values, dynamically building queries with user-controlled table names or column names must ensure those entities are strictly validated or correctly quoted, as standard parameterized execution does not protect against structural injection.
**Prevention:** Keys used to dynamically construct SQL components (like SET clauses) must be explicitly quoted and internal quotes must be escaped (e.g. `'"{}" = ?'.format(k.replace('"', '""'))`) before string interpolation. Inline comments like `# nosec B608` can be utilized to suppress static analysis false positives if it's securely mitigated.
