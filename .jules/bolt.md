## 2024-05-24 - Database Optimization: Composite Indexes for Count Queries
**Learning:** The `logs_client_issues` and `memory_quarantine` SQLite tables frequently execute count queries filtering on `(client_id, tenant, project_id, status)`. These queries will perform full table scans without an appropriate index, which becomes a bottleneck as the tables grow. A composite index on these fields is necessary to significantly speed up count queries. (Note: Indexing `(tenant, project_id)` for the FTS `search_keyword` function was previously benchmarked and did not yield performance improvements, but indexing `(client_id, tenant, project_id, status)` for `logs_client_issues` and `memory_quarantine` is highly effective).
**Action:** When working on performance optimizations for SQLite tables with frequent specific filtering queries, prioritize adding targeted composite indexes to support those specific queries, rather than generic single-column indexes.
