## 2024-05-25 - SQLite Missing Composite Indexes
**Learning:** The memory service performs multi-tenant queries filtering by `tenant`, `project_id`, and `status` or timestamps, but lacked composite indexes for these combinations on large tables like `logs_client_issues`, `logs_access`, `memory_quarantine`, and `logs_agents`. This resulted in slow queries due to full table scans. Legacy schema simulation tests also fail with `sqlite3.OperationalError` if columns are indexed before verifying they exist with `_column_exists()`.
**Action:** Always append composite indexes covering the multi-tenant isolation columns `(tenant, project_id)` often alongside timestamps or status fields in heavily queried SQLite tables to optimize lookup speed without destroying single-column filter performance. Ensure all index columns are verified using `_column_exists()` before creating the index.
