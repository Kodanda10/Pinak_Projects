## 2024-05-24 - Optimize multi-tenant SQLite queries with covering indexes
**Learning:** SQLite single-column indexes on `status` fields cause inefficient linear scans for multi-tenant filters like `client_id`, `tenant`, and `project_id`. When optimizing queries that filter by all these fields (e.g., `count_client_issues`, `count_quarantine`), a single-column index on `status` will just search by `status` and linearly scan the rest.
**Action:** Use composite/covering indexes `(client_id, tenant, project_id, status)` for these tables (`logs_client_issues`, `memory_quarantine`) to enable covering index usage for frequent multi-tenant lookups and significantly improve performance, especially as dataset sizes grow. Remember to rename the index when changing from single-column to composite to ensure it gets applied correctly using `CREATE INDEX IF NOT EXISTS`.
