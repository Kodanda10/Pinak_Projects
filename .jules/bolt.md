## 2024-10-17 - Missing multi-tenant composite indexes
**Learning:** Found an opportunity to optimize database queries. Heavily queried multi-tenant tables (`logs_access`, `memory_quarantine`, `clients_registry`, `logs_agents`, `logs_client_issues`) lack composite database indexes covering the multi-tenant isolation columns `(tenant, project_id)`. Appending new composite indexes (`tenant`, `project_id`, `ts`/`status`) rather than replacing existing ones prevents performance regressions and N+1 queries.
**Action:** Append the new `CREATE INDEX` statements to `Pinak_Services/memory_service/app/core/database.py` and verify functionality. Ensure column existence using `self._ensure_column` or `self._column_exists()` before creating the indexes in `_init_db` to support legacy schema tests.
