## 2024-09-05 - Vector Store Batch Addition Buffering
**Learning:** In the memory_service `VectorStore` class, directly using `np.vstack` and `np.concatenate` in `add_vectors` (an O(N) array reallocation) creates a massive performance bottleneck when processing multiple individual vectors sequentially, as occurs during standard indexing or continuous updates. This causes high CPU overhead and slows down data ingestion significantly.
**Action:** Implemented a robust O(1) list-based buffering strategy (`_vector_buffer`, `_id_buffer`, `_norm_buffer`) directly within the `VectorStore` memory structure. We accumulate new vectors in lists and provide an explicit `_flush_buffers()` method. `_flush_buffers` handles the heavy O(N) array reallocation all at once, drastically reducing overhead. Crucially, this optimization required augmenting properties like `ntotal` and all read/state-changing methods (`search`, `reconstruct`, `remove_ids`, `save`) to ensure buffers are flushed before state access, preserving strict consistency and functionality while unlocking substantial throughput improvements.
