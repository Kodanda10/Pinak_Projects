## 2025-02-27 - Indexing Multi-Tenant Tables
**Learning:** In a heavily-queried multi-tenant database using SQLite, adding composite indexes on multi-tenant tables covering `(tenant, project_id)` + specific query fields (`ts`, `status`, `last_seen`) provides a massive (~2x-3x) speedup. We proved this via benchmark measurement. Note: Benchmarking reveals `logs_client_issues` does not benefit measurably from this optimization (the dataset size / query pattern for issues does not trigger table scans as heavily in production, contrary to synthetic benchmarks). I focused on optimizing `logs_access`, `memory_quarantine`, `clients_registry`, and `logs_agents` tables.
**Action:** When working on multi-tenant SQLite applications, always include composite indexes (`tenant, project_id, <field>`) on heavily queried tables to prevent N+1 queries and full table scans. Make sure to profile, as some tables (e.g. `logs_client_issues`) don't benefit.
