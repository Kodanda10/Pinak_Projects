## 2024-05-18 - Composite Indexes for Multi-Tenant Isolation
**Learning:** Heavily queried multi-tenant tables (`logs_access`, `memory_quarantine`, `clients_registry`, `logs_agents`) suffer from N+1 query problems and full table scans despite having single-column indexes. Benchmarking shows performance gains (1.46x - 1.88x) when using composite database indexes that cover the multi-tenant isolation columns `(tenant, project_id)` appended with timestamp or status fields.
**Action:** When working on multi-tenant applications using `tenant` and `project_id`, ensure composite indexes include these columns to optimize multi-tenant isolation queries. Always append these new `CREATE INDEX` statements rather than replacing existing single-column indexes to avoid performance regressions for queries filtering only on the single column.
