## 2024-07-27 - Composite Indexes for Multi-Tenant Data
**Learning:** In a multi-tenant SQLite architecture, filtering by `tenant` and `project_id` across all memory tables (e.g. `memories_semantic`, `memories_episodic`) requires composite indexes prioritizing these common filters to avoid full table scans as dataset grows. Also, when modifying schemas by adding composite indexes that reference columns not present in mocks, tests with inline mocked SQLite schemas must be updated to include the newly indexed columns to prevent `sqlite3.OperationalError: no such column`.
**Action:** When adding composite indexes for multi-tenant tables, ensure the schema includes `(tenant, project_id)` first, and always update any inline mocked schemas in the test suite to include the indexed columns.
