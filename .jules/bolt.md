## 2024-05-24 - Composite Indexes for Multi-Tenant Data
**Learning:** The database uses multiple multi-tenant tables (`logs_access`, `memory_quarantine`, `clients_registry`, `logs_agents`, `logs_client_issues`) but many queries lack composite indexes, leading to potential N+1 query problems and full table scans. When adding composite indexes to optimize these tables, it's important to keep the existing single-column indexes, as replacing them can introduce performance regressions for queries that filter only on the single column. Also, test schemas might be missing columns, so we must check `_column_exists` before adding an index involving those columns.
**Action:** Add `CREATE INDEX` statements for composite indexes involving `tenant`, `project_id`, and other frequently filtered columns to `_init_db`. Guard the creation with `_column_exists` checks to avoid test failures.
