## 2023-11-01 - Optimizing Multi-Tenant Queries
**Learning:** Heavily queried multi-tenant tables (such as `logs_access`, `memory_quarantine`, `clients_registry`, `logs_agents`) experience significant performance regressions due to full table scans without composite indexes spanning `(tenant, project_id)` plus a relevant trailing column (like `status` or `ts`). Replacing single-column indexes degrades simple queries, so composite indexes must be appended explicitly alongside `self._column_exists()` checks to prevent initialization failures during schema migrations.
**Action:** When adding or discovering heavily queried multi-tenant tables, explicitly add composite database indexes covering the multi-tenant isolation columns `(tenant, project_id)`—often appended with timestamp or status fields—to prevent N+1 queries and full table scans. Ensure these additions include proper schema checks and preserve any existing single-column indexes.
