## 2023-10-21 - Database Composite Index Optimization
**Learning:** The VectorStore uses a linear Numpy scan for search, which is an O(N) operation and slow for many vectors. Although faiss-cpu is a project dependency, replacing NumPy with FAISS for large indices could be a significant boost. However, database operations on multi-tenant tables (`logs_access`, `memory_quarantine`, `logs_client_issues`, `logs_agents`, `clients_registry`) lack composite indexes on `tenant` and `project_id`, which are frequently queried together, leading to N+1 queries or full table scans. Adding composite indexes is a measurable >50% performance improvement (from 0.20s to 0.05s in benchmark).
**Action:** When working on Pinak Services database schemas, ensure that heavily queried multi-tenant tables have composite indices for tenant and project_id, possibly appended with time/status depending on sort or filter criteria.
