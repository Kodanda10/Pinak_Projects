## 2024-10-31 - Missing Composite Indexes on Multi-tenant Tables
**Learning:** In a heavily-queried multi-tenant database using SQLite (e.g., in `Pinak_Services/memory_service/app/core/database.py`), isolated tables relying only on single-column indexes (like `created_at` or `status`) experience severe performance degradation (full table scans or inefficient filtering) when queried by multi-tenant isolating columns `(tenant, project_id)`. Adding composite indexes covering these combinations `(tenant, project_id, [status, timestamp])` provides a massive 50x-110x speedup in read operations.
**Action:** When working on multi-tenant backends, especially SQLite databases within the Pinak services, always review the most frequent query patterns and ensure composite indexes covering the isolation columns `(tenant, project_id)` alongside other filtering or sorting columns are created.
