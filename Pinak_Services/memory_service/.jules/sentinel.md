## 2024-08-14 - Fix dynamic column SQL Injection in UPDATE statement
**Vulnerability:** The `DatabaseManager.update_memory` method constructs an SQL `UPDATE` statement dynamically using dictionary keys (`updates.keys()`). These keys are directly interpolated into the query string (`f"{k} = ?"`), creating a SQL injection vulnerability if an attacker supplies maliciously crafted keys.
**Learning:** When dictionary keys or user inputs are used to dynamically build SQL statements (e.g., SET clauses), they must be explicitly quoted to prevent SQL injection, even if parameterization (`?`) is correctly used for values. Bandit rule B608 may also flag safe string interpolations (e.g., table names from a whitelist) as false positives.
**Prevention:** Explicitly wrap dynamic identifiers (column names) in SQLite double quotes (`"`), resulting in `f"\"{k}\" = ?"`, and apply `# nosec B608` to suppress static analysis false positives when interpolating whitelist-validated table names.
